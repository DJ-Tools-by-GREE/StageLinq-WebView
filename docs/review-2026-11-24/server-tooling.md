# Server, settings, tooling and integration review

Review date: 2026-11-24. Baseline: WebView 78b7bd0. P1 means can interrupt a show or lose saved data; P2 means substantial correctness/performance issue; P3 means bounded tooling/maintenance issue. Locations describe baseline symbols, with current paths linked by the combined report.

## SV-01 — P1 — Corrupt/commented config is overwritten by a freewheel update — fixed
GlobalSettingsStore.persist() caught parse/read errors and wrote only freewheel, dropping playlists, targets and mappings. Reproduction: save commented config with playlists, change freewheel; only freewheel survives. The new jsonc-parser reader preserves quoted comment-like strings, accepts comments, rejects malformed/non-object config, and updates only the requested section. Comments/formatting are normalized to ordinary JSON on a successful save; semantic content is retained. A malformed file stays byte-for-byte unchanged. Regression tests cover both cases.

## SV-02 — P1 — Disk failures are acknowledged as successful settings saves — fixed
Both settings stores returned a catch handler that swallowed filesystem failures and changed in-memory state first. Their HTTP routes could return success despite ENOENT/EACCES/rename failure. Changes now queue complete operations, propagate failures, and commit the cached value only after atomic disk replacement. User settings loading no longer resets an unreadable/malformed file. Failed user/global writes return HTTP 500 without changing the previous runtime setting. Recovery after a failed queued operation is tested.

## SV-03 — P1 — Concurrent config writers collide on config.json.tmp — fixed
Bulk config PUT and freewheel writes used the same temporary filename with independent queues. One rename could consume the other's file; the second failed or persisted the wrong data. A shared per-path operation queue and unique temporary filenames now cover both writers. Final peer review also moved reload reading and runtime application inside the complete settings-operation queue; PR-02 proves a pending PUT90 followed by reload cannot restore stale30. Read-modify-write occurs inside that queue. Concurrent full save then section update preserves both changes in the test. Explicit full config replacement still has documented last-writer semantics; cross-browser merge/version conflicts are a remaining product decision.

## SV-04 — P1 — Invalid config reload silently clears live mappings — fixed for parse/shape failures
loadRootConfig() swallowed all errors, returned null/defaults, and reload replaced active mappings while reporting success. It now distinguishes missing-at-first-boot from invalid/unreadable configuration; reload of its established path fails explicitly and leaves the previous values in place. Known nested collection/scalar shapes are validated before applying. The old regex comment stripper also removed comment markers inside strings; a maintained JSONC parser replaces it. HTTP integration reproduces rejected malformed reload and later successful recovery.

## SV-05 — P1 — Async Express handlers can terminate the server on rejection — fixed
Express 4 does not automatically forward a rejected async handler. Several recording/settings routes awaited fallible operations without a catch. A common asyncRoute forwards rejections to JSON error middleware; test covers rejected persistence and real HTTP 500 responses. Recording resume-abort is awaited before success is returned. This is necessary for the corrected stores/recorder to expose failures safely.

## SV-06 — P1 — Graceful shutdown exits before recorder flushes — fixed
The initial SIGINT/SIGTERM handler started recorder.stop() but later sACN-only handlers immediately called process.exit. Non-sACN mode also lacked complete shutdown. One coordinated handler now stops accepting work, ends timers/clients/output, awaits serialized recorder shutdown, closes workers/bridge, then exits. A 10-second hard ceiling catches stuck cleanup and exits nonzero. Real child-process test with hardware methods stubbed records a footer and sidecar, removes recovery lock, and exits 0 after SIGTERM. Sudden SIGKILL/power loss still relies on orphan recovery.

## SV-07 — P1 — sACN OFF can be ignored or read from the preceding channel — fixed using package API
sacn's Packet.payload intentionally omits zero-valued channels. The address/address-minus-one fallback therefore either ignores OFF or reads the previous channel; guessing percentages versus bytes also makes raw low values ambiguous. The installed package already exposes exact raw bytes as payloadAsBuffer. The server now reads address-minus-one from that buffer and uses documented 0–50 off / remaining deck bands. Tests encode/decode real sacn Packet objects at every boundary, including address 2 zero while address 1 is 255. This is a concrete standardized replacement.

## SV-08 — P2 — sACN simulator D1 emits the OFF value — fixed
D1 used raw DMX 50, inside documented off band. It now uses 76, centered in Deck 1's 51–101 band. All simulator values map to their intended deck in a regression test.

## SV-09 — P1/P2 — File logger's asynchronous stream error can crash recursively — fixed
fs.createWriteStream had no error listener; try/catch around write cannot catch asynchronous ENOTDIR/EACCES/full-disk errors. Uncaught-error handling logged through the same failed stream. The stream now has a nonrecursive error handler that disables file logging for the run and reports once to stderr; terminal logs continue. Subprocess test with a non-directory logs path exits successfully and emits a subsequent log. Remaining suggestion: bound queued bytes/rotation for sustained slow storage; no maximum logfile/retention policy is currently implemented.

## SV-10 — P2 — Slow WebSocket clients accumulate unbounded outgoing frames — fixed
All send paths now use a per-socket serialized queue with snapshot coalescing, pending-byte/frame bounds and a send deadline. Large media can drain on an idle healthy socket; a peer-review regression specifically exercises four realistic 13.87 MB waveform frames plus concurrent snapshots. The initial naive single-frame size cap was rejected because it caused reconnect loops; see PR-01. Queue overflow/stalled clients disconnect so memory is bounded. Incoming control messages are capped at 16 KiB. Tests cover draining, coalescing, overload, callback errors and close cleanup.

## SV-11 — P2 — Old waveform tasks remain current after cached/gated track changes — fixed at callback boundary
The task generation counter advanced only after cache/suppression early returns. A previous download could overwrite a newer track's status. It now advances before every track-change branch. Frontend identity guards are covered in the frontend report. Remaining: basename-only cache identity and unload notification semantics require the cross-module media improvements described in the media report.

## SV-12 — P2 — No-op diagnostic work still runs at 30 Hz — fixed core cost
The snapshot loop cloned/serialized comparison data even with uiOut disabled and formatted the terminal dashboard while headless/disabled. Those paths now run only when enabled. logDashboard's condition previously throttled identical content only, allowing changing content at the full source rate; it now enforces a genuine 100ms redraw minimum. This is a code-path/work-count result, not a measured hardware FPS claim.

## SV-13 — P2 — Fixed Art-Net type byte disagrees with configured FPS — fixed for supported integer rates
artnetFpsType=0x03 labeled every frame as 30fps, even at 24/25. The byte now follows 24/25/30. Unsupported values fail with a clear startup error, including 29.97, which needs genuine drop-frame numbering rather than a nominal byte change. Current 30fps configuration is unchanged. The frontend/domain-schema report tracks remaining form constraints.

## SV-14 — P2 — Replay fidelity, clock ownership and recorder/ARM races — fixed with user-selected behavior
User explicitly chose recorded offsets and mutually exclusive recording/armed replay. Server output switches all deck states, timing and offsets atomically on replay entry/exit, and restores live config on detach even without a subsequent bridge event; reload does not replace active recorded offsets. Recorder pending operations reserve its busy state synchronously; arm reserves its loading state synchronously. Initial selected deck is captured in recording and recovery keyframes. stateProvider provides both states and source timing to the worker. See media/timing reports and tests for the engine details.

## SV-15 — P3 — Build can use stale sibling library output and miss frontend type errors — fixed
npm run build now rebuilds ../StageLinq first, typechecks frontend, then builds both workspaces. fresh runs npm ci in the sibling before WebView. Root npm test runs durable backend/frontend regressions (build first). Local dependency workflow is the user's explicit choice; cloning/installing a standalone WebView repository without its sibling remains unsupported by design.

## SV-16 — P2/P3 — Dependency advisories — partly fixed; remaining dev-tool migration documented
The original installation audit reported 13 affected dependency nodes (1 critical, 7 high, 4 moderate, 1 low), not 13 proven exploitable application paths. Compatible updates addressed body-parser/ws/proxy-addr/Babel/PostCSS/Browserslist/nanoid/source-map dependencies. Artwork uses a patched file-type >=21.3.1; the older initially suggested version was not retained as the backend's dependency. Audit details and final remaining counts are recorded in the top-level report. Vite/esbuild major migration is not silently forced; recommended follow-up is an isolated supported Vite/plugin/tsx update with HMR, proxy and production-build checks. The linked StageLinq package has a separate lock/dependency tree and is not comprehensively covered by WebView npm audit; see retained upstream file-type note.

## SV-17 — P2 — Runtime config has incomplete domain validation — open/partly mitigated
Fixed parse errors, array/object/primitive shapes, integer playlist index, and supported Art-Net FPS. Still missing a single authoritative schema for IP addresses, port/universe/DMX ranges, all env overrides, finite positive sendHz, stream IDs, frame-offset ranges, duplicate recording mappings and unknown fields. Number(env) can produce NaN/out-of-range values. Suggested fix: a reusable schema (e.g. Zod or JSON Schema/Ajv) for file, API and env normalization, returning field-specific errors before any network service starts; mirror constraints in forms. Avoid silent clamping of lighting addresses. Domain constraints need explicit documented supported behavior.

## SV-18 — P3 — show runner assumes macOS and can kill an active show — open
scripts/show.mjs uses caffeinate on all non-Windows platforms; Linux enters a failing restart loop. It also kills an existing tmux session unconditionally. Windows restarts after all exits and has no parent-signal coordination. Suggested fix: platform-specific macOS caffeinate, plain runner/systemd on Linux, spawn error handling and parent shutdown propagation; attach to an existing session unless an explicit restart option was requested. Switching live-show restart semantics requires operator agreement. No change applied to this helper.

## SV-19 — P3 — Diagnostic Art-Net monitor conflates frame jumps with packet loss — open
receiveArtnet.js treats positive frame differences >1 as lost packets. Pitch >0, legitimate seek, track/offset changes, multiple senders/stream IDs, or different sendHz can produce the same pattern. Its clock/rate history is global across sources. Suggested fix: label this metric frame discontinuities, key by sender/stream/type, report cadence gaps separately, and annotate intentional seek/loop rather than asserting packet loss. SSE writes also need a queued-byte budget/slow-client eviction. The monitor's bounded 1200-entry chart is otherwise independent of production outputs. No actual dropped-packet count is claimed by this audit.

## SV-20 — P3 — Standalone Python cue helper has ambiguous lookup/resource behavior — open
read_cues.py opens SQLite twice per track in writable/default mode; closes are skipped on exceptions; a LIKE fallback picks the first ambiguous filename and treats percent/underscore as wildcards. It can accept infinite positions from corrupt blobs. Suggested fix: one context-managed read-only connection, joined exact match, reject ambiguity and non-finite positions, validate/decompress with a size limit. The maintained TypeScript extractor is the documented application path; upstream DbConnection is writable and does not decode quickCues, so it is not a safe standardized replacement. No Python source changed.

## SV-21 — P3 — Generated logs/recordings are tracked despite docs claiming gitignored — open
.gitignore has log/recording exclusions commented out, and git tracks historical backend logs plus a 72-minute recording. These enlarge history and can capture filenames/IPs. Suggested fix: decide whether these are intentional fixtures; move a minimal scrubbed recording into a fixtures directory, enable ignores for generated files, and stop tracking only with explicit user approval. Do not delete history or user recordings as an incidental cleanup. This review preserves existing artifacts and only removes test-generated files created during this run.

## Coverage and validation
Read complete backend index, settings stores, logging, constants, root/backend/frontend manifests and tsconfigs, Vite configuration, show runner, both receive utilities, Python cue helper, config/users, ignore rules, repository guides/memories and relevant package APIs. All remaining production TypeScript/TSX/CSS and CLI code is assigned to the three agent reports. Historical logs and the checked-in recording were inspected as evidence/data, not counted as independently executable code. project.zip is a historical snapshot, not a second active implementation.

Server regressions cover destructive saves, JSONC quoting, concurrent writers, failed cache commits/recovery, Express rejection forwarding, real sACN boundaries, WebSocket queue bounds and logger stream failure. A real HTTP child server bound only to loopback, with StageLinq connect/disconnect stubbed and Art-Net/OSC disabled, validates error responses, reload recovery, recorder/ARM exclusion and SIGTERM flush. No Denon, sACN sender, Art-Net or OSC hardware traffic is required by these tests.
